## 4. 当前产品与技术事实

1. **观察事实**：应用当前首先是“荧光检测工作台”；BFN-IR 2.0 是主导航“网络设计”下的一张长页面，不是独立产品壳。
2. **观察事实**：应用没有 URL Router。页面切换由 Zustand 中的 section 状态驱动，BFN 内部再用四个本地 tab 切换。
3. **观察事实**：BFN 项目和运行记录存放在浏览器 `localStorage`；SQLite/Supabase 面向荧光检测记录，不提供 BFN 项目、实验数据集、模块或网络的结构化 CRUD。
4. **观察事实**：当前 BFN 只有一个演示项目。实验数据列表/详情、模块列表/详情、网络列表/详情并非独立路由或持久化实体页。
5. **观察事实**：模块与证据库来源于仓库 fixture 和本地注册表展示，不能被描述为已连接真实实验数据库。
6. **观察事实**：完整模型、理想恒等连接、端口三元组、静态/动态分离、ANNApproximation、双参数空间反向设计已经进入领域代码和现有测试。
7. **观察事实**：界面包含中文与英文资源，但当前 BFN 页面大量使用全大写英文眉题、内部枚举和值作为可见文案。

## 5. 跨页面最高优先级问题

| 优先级 | 观察事实                                                                                   | 设计判断                                                                     | 风险                                             |
| ------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------ |
| P0     | BFN 页面持续显示荧光设备、连接、采集、电量状态                                             | BFN 任务需要独立的项目/对象上下文条；设备状态不应成为网络建模的全局首要信息  | 用户无法快速确认当前建模对象和保存状态           |
| P0     | 一张长页面同时承载项目摘要、四步导航、模式、导入/重置、旧数据警告、编辑器和结果            | 将对象导航、任务导航和结果状态分层；首屏必须进入当前任务                     | 理解成本高，关键操作被折叠到首屏下方             |
| P0     | IdealEdge 检查器仍可见 `weight`、`bias`、`delay`、`noise` 字样，虽然以禁用占位表达“无参数” | 理想连接检查器中彻底移除这些字段，只显示来源/目标端口与匹配状态              | 禁用字段仍强化“连接本来可以有权重”的错误心智模型 |
| P0     | 多输入关系直接显示 `independent_unverified`                                                | 用户界面必须显示“默认独立，输入间交互关系未验证”                             | 内部枚举难理解，也容易被误读为已验证结论         |
| P0     | 反向设计演示候选的各维度都是数值；底层类型目前要求 `number`                                | 在接入真实候选前先允许 unknown/null 语义并定义展示；本 UI 阶段不擅改科学类型 | 缺失信息未来容易被错误填充为 0                   |
| P1     | 页面使用深色网格、青色发光边框、洋红高亮和大量阴影                                         | 改为中性、克制、长时工作友好的科学工作台；洋红只保留给荧光/响应曲线          | 视觉装饰与业务状态竞争                           |
| P1     | 当前页头和分析设置区都存在“运行完整模型”                                                   | 每个任务区保留一个明确主按钮，并按静态/动态任务命名                          | 用户无法判断两个按钮是否执行相同动作             |
| P1     | “重置演示项目”与“导入 BFN-IR”同处普通工具条                                                | 放入危险操作区并明确会覆盖哪些本地内容、是否可恢复                           | 破坏性范围不清楚                                 |
| P1     | 结果成功条、演示边界、适用域、旧项目提示在多个层级重复                                     | 状态靠近对象和结果集中呈现，保留一个全局演示标识                             | 信息噪声掩盖真正的外推/证据警告                  |
| P1     | 1440、1280、960 三个视口中均检测到 73 个小于 12px 且有文本的可见元素                       | 元数据最小 12px，主要字段 13–14px；减少全大写英文微文案                      | 长时间使用可读性不足                             |
| P2     | BFN 导入的隐藏文件控件在可访问树中显示英文 “Choose File”                                   | 隐藏控件也需要本地化可访问名称，且不应形成重复按钮                           | 屏幕阅读器和键盘用户遇到重复、跨语言动作         |
| P2     | 主内容中嵌套另一个 `main`，网络画布使用 `role=application`                                 | 每页只保留一个 main；仅在确有复杂键盘模式时使用 application 并提供操作说明   | 地标导航和辅助技术模式可能混乱                   |

2. **页面名称**：当前可见“检测记录”。
3. **页面主要任务**：检索本地检测记录和查看三通道曲线。
4. **当前主要对象**：`DetectionRecord`，不是 BFN 实验数据集。

6. **当前次要按钮**：搜索、信号类型和通道切换。
7. **页面状态**：3 条演示记录、分析完成、本机存储。
8. **信息层级问题**：记录的峰值/时长优先，缺少输入/输出、条件数、上下文、校准和证据来源。
9. **布局问题**：列表/详情工作台结构可复用，窄屏下需重新排列。
10. **文案问题**：“检测记录”不能重命名后冒充实验数据集。
11. **按钮语义问题**：导出动作清楚；缺少数据集级“查看模型引用”。
12. **表单问题**：搜索框没有可见标签。

15. **可访问性问题**：listbox/option 结构清楚；搜索框应补可见标签。
16. **可复用组件**：双栏列表详情、曲线图、元数据面板、导出动作。

## 7. 响应式与可访问性结论

### 7.1 视口测量

| 视口     | 页面横向溢出 | `.page-viewport` | 网络编辑器表现                                          | 可见小于 12px 的文本元素 |
| -------- | ------------ | ---------------- | ------------------------------------------------------- | ------------------------ |
| 1440×900 | 无           | 1186 / 1186 px   | 三栏可见，仍需页面纵向滚动                              | 73                       |
| 1280×800 | 无           | 1184 / 1184 px   | 主导航折叠为图标，三栏压缩，画布内部横向滚动            | 73                       |
| 960×640  | 无           | 864 / 864 px     | 右检查器下移，页面高度约 1551px，画布右侧对象首屏不可见 | 73                       |

**设计判断**：当前“无 document 级横向溢出”是积极基础；内部画布滚动和面板重排仍使 960px 下的对象—画布—检查器关系断裂。最小窗口应保留可折叠检查器抽屉和固定任务栏，不能仅把三栏纵向堆叠。

### 7.2 可访问性积极项

- 有“跳到主要内容”链接。
- 主导航、tablist、表单标签、status/alert 和大多数图表具有语义名称。
- 画布节点与连接可在可访问树中识别。
- 禁用按钮暴露 disabled 状态。
- 颜色之外通常还有中文状态文字。

### 7.3 可访问性问题

- 页面存在嵌套 `main` 地标。
- 隐藏文件输入暴露英文 “Choose File”，与可见中文按钮重复。
- 网络画布使用 `role=application`，未提供键盘模式说明、快捷键或退出方式。
- 四个工作流 tab 视觉上更像大型操作卡；需要检查左右方向键、Home/End 和焦点管理。
- 多处 10–11px 全大写英文元数据影响阅读。
- 图表需要完整文本摘要，特别是外推、参数区间和 ANN 拒绝结论。
- 模式、状态和按钮样式过度依赖青色发光高亮。

## 10. 需要用户确认的产品决策

1. **产品壳**：BFN 是继续作为荧光桌面应用中的独立工作区，还是成为可切换的顶级产品模式？建议先采用“同一应用、独立 BFN 工作区壳”，避免误删现有检测能力。
2. **项目数量**：近期是否只维护一个本地 BFN 项目，还是需要多项目/多网络列表、版本与归档？这会决定路由、repository 和迁移范围。
3. **实验数据持久化**：是否批准新增 BFN 专用实验数据集实体与 SQLite schema？在批准前，UI 只能将现有 fixture 明确标为演示只读数据。
4. **模块编辑能力**：PR 5 是先做只读模块详情，还是同时交付创建、编辑、版本保存和引用检查？后者需要持久化与领域校验设计。
5. **反向设计缺失值**：是否批准将候选评价类型扩展为 `number | unknown`/可选值？这是正确展示“未知”的前置条件，不能只在 UI 层用 0 模拟。
6. **最低支持宽度**：是否继续承诺 960×640？建议保持应用可打开，但把完整网络编辑器的推荐工作区定义为 ≥1280×800，并在 960px 使用抽屉式检查器。

## 11. 阶段一结论

现有代码已经具备较完整的 BFN-IR 2.0 科学内核和可运行演示流程，主要缺口集中在产品身份、对象层级、任务分区、科学边界表达和长期工作可读性。阶段二应先统一术语、按钮、状态、错误和边界组件；阶段三再调整应用框架。底层科学计算与检测数据持久化在本阶段保持不变。
