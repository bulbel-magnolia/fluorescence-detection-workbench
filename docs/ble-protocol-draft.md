# HC-08D BLE 透传协议草案

状态：`HC08D-ASCII-DRAFT-0.2` 已按 STM32 固件接口实现；解析器兼容当前实测的空格分隔帧和早期草案中的逗号分隔帧。GATT UUID 与科学换算仍按版本化输入管理。

## 角色与数据路径

- Windows 应用：BLE Central / GATT Client
- HC-08D：BLE Peripheral / GATT Server 与 UART 透传模块
- STM32F103C8：数据产生与命令执行
- AS7341：I²C 光谱传感器

```text
Windows 桌面应用 ↔ BLE GATT ↔ HC-08D ↔ USART1 ↔ STM32F103C8 ↔ I²C1 ↔ AS7341
```

不引入浏览器桥接、手机中继或云端中继。同一 HC-08D 联调时，手机和电脑不能同时保持连接。

## 已确认硬件配置

| 项目       | 配置                                             |
| ---------- | ------------------------------------------------ |
| 主控       | STM32F103C8；Keil 工程已编译通过                 |
| UART       | USART1；PA9 发送、PA10 接收                      |
| 串口参数   | 9600 baud / 8 data bits / no parity / 1 stop bit |
| 流控制     | none                                             |
| 传感器     | AS7341                                           |
| I²C        | I²C1；PB6/PB7；100 kHz                           |
| 发送频率   | 约每 0.5 秒一帧，约 2 Hz                         |
| 数值范围   | 十进制无符号 16 位整数，0–65535                  |
| 数字饱和值 | 65535                                            |

## GATT 发现

FFE0/FFE1 是当前 HC-08 系列透传模块的优先联调值，不在软件中描述为最终量产 UUID。

| 项目              | 当前策略                                                             |
| ----------------- | -------------------------------------------------------------------- |
| 广播识别          | 优先 `HC-08D`、`HC-08`、`HC08` 等名称；名称缺失时兼容广播服务 `FFE0` |
| Service           | 优先短 UUID `FFE0` 或 Bluetooth Base UUID 的完整表示                 |
| Notify / Indicate | 优先 `FFE1`；否则在同一服务中寻找唯一可通知特征                      |
| Write             | 优先 `FFE1`；否则在同一服务中寻找唯一 Write/Write Without Response   |
| 单特征双向        | 支持同一特征同时承担通知和写入                                       |
| 多个有效组合      | 返回候选列表，由用户在技术详情中选择；软件不猜测                     |

Windows 界面只保存本次会话的不透明设备 ID，不把完整 MAC 地址写入源码、文档或记录。

## 上行数据帧

编码：ASCII。当前硬件实测帧使用空格分隔：

```text
480:<uint16> 515:<uint16> 555:<uint16> CLR:<uint16>\r\n
```

实测样例：

```text
480:1545 515:6733 555:65535 CLR:65535\r\n
```

解析器同时保留对早期逗号分隔格式的兼容：

```text
480:<uint16>,515:<uint16>,555:<uint16>,CLR:<uint16>\r\n
```

两种格式的字段顺序均固定：

| 字段 | 当前含义              |
| ---- | --------------------- |
| 480  | 480 nm 通道原始数字量 |
| 515  | 515 nm 通道原始数字量 |
| 555  | 555 nm 通道原始数字量 |
| CLR  | 总体亮度原始数字量    |

`65535` 表示数字饱和。解析器保留该值、标记对应字段并继续绘图，不自动截断、替换或丢弃整帧。

当前软件以 `a.u.` 作为界面显示占位单位。最终科学单位、增益、积分时间、背景定义和量程解释需要与硬件及实验标定共同版本化。

## 下行命令与响应

编码：ASCII。每条命令和响应均以 CRLF `\r\n` 结束。

| 动作     | Windows 写入   | STM32 成功响应   |
| -------- | -------------- | ---------------- |
| 打开 LED | `@LED_ON\r\n`  | `LED_ON_OK\r\n`  |
| 关闭 LED | `@LED_OFF\r\n` | `LED_OFF_OK\r\n` |

未知命令响应：

```text
ERROR_COMMAND\r\n
```

当前固件不支持 START、STOP、ZERO、CALIBRATE 或 GET_STATUS。Windows 真实模式的开始和结束仅控制本机记录边界；ZERO 与 CALIBRATE 不写入硬件。

## 应答语义

当前固件响应不含命令 ID。软件使用单一在途命令保证响应归属：

1. 写入 GATT 成功后，界面状态为 `accepted`，表示字节已交给传输层。
2. 收到与当前命令匹配的 `LED_ON_OK` 或 `LED_OFF_OK` 后，状态为 `completed`。
3. `ERROR_COMMAND` 返回 `DEVICE_COMMAND_REJECTED`。
4. 收到与当前命令不匹配的成功响应时，记录 `UNMATCHED_COMMAND_RESPONSE`，不完成当前命令。
5. 2 秒内没有匹配响应时，返回 `COMMAND_RESPONSE_TIMEOUT`。

固件将来增加命令 ID 后，可升级协议以实现显式 ACK 关联；本草案不伪造当前固件没有的字段。

## 缓冲、分片与错误恢复

BLE Notification 可能拆分一行，也可能一次携带多行。协议层负责：

- 跨通知保存未完成文本；
- 以 LF 为主要行边界，并去除 CRLF；
- 识别同一通知中的多行；
- 对相邻 `480:` 帧提供兜底分界；
- 不使用通知静默时间判断帧结束，未出现协议边界的内容继续留在缓冲区；
- 拒绝非法 UTF-8、字段缺失、非整数或超出 0–65535 的值；
- 将接收缓冲限制为 8192 字节；
- 发生单行错误后继续解析后续有效帧。

每个有效帧附加应用侧 `sequence`、`receivedAt` 和 `elapsedMs`。这些字段用于记录与绘图，不宣称来自 STM32 时钟。

## 连接与恢复

- 完整帧超过约 1.5 秒未到达时，界面提示数据中断，连接不立即判死。
- 意外断线后按约 1、2、4 秒安排三次自动重连。
- 显式断开、模式切换和运行时销毁不会触发重连。
- 每次连接使用代次标识，旧连接事件不会覆盖新状态。
- 原始行监视器最多保留 200 行且总量不超过 64 KiB。
- 本机会话内最多保留 3600 个原始帧，图表每通道保留最近 300 点。

## 当前记录边界

真实会话保存：

- 四路原始数字量；
- 应用接收时间与相对时间；
- 数字饱和字段；
- 原始文本行；
- 当前协议版本。

真实会话不生成背景值、校正信号、浓度、质量分或等级，记录状态为 `RAW_ONLY`。
